⏱ 시간/공간 복잡도
시간 O(n²) 공간 O(n) 이중 반복문으로 인해 입력 크기에 따라 급격히 느려집니다.
✎ 스타일 / 가독성 피드백
·변수명 count, n은 명확하지만 need, seen처럼 의도를 드러내는 이름을 더 쓰면 좋습니다.
·중첩 반복문 depth가 깊어질수록 가독성이 떨어지니 조기 종료(early return) 활용을 고려하세요.
·매직 넘버 없이 파라미터화가 잘 되어 있는 점은 좋습니다.
◆ 감지된 패턴 & 개념 진단
완전탐색 (Brute Force) 감지된 접근법
이 문제는 값 하나를 저장해두고 나머지를 순회하며 확인하는 해시맵 기반 풀이(투 포인터/해시)로 O(n)에 풀 수 있는데, 현재 코드는 모든 쌍을 이중 반복문으로 확인하는 완전탐색 방식을 사용해 시간 복잡도가 불필요하게 높습니다.
↻ 개선 방향 제안
이미 등장한 값을 해시맵에 저장해두고, 매 원소마다 '필요한 나머지 값'이 맵에 있는지 O(1)에 확인하는 방식으로 바꾸면 이중 반복문을 제거할 수 있습니다.
리팩토링 예시
def solve(nums, k):
    seen = {}
    count = 0
    for x in nums:
        need = k - x
        if need in seen:
            count += seen[need]
        seen[x] = seen.get(x, 0) + 1
    return count  # O(n^2) -> O(n)
